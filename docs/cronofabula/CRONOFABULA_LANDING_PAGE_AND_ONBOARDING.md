# CRONOFÁBULA — LANDING PAGE AND ONBOARDING

## 1. Resumo Executivo

Este documento define a **landing page**, o fluxo de entrada e o onboarding inicial do **Cronofábula**.

O objetivo é apresentar o produto com clareza, converter visitantes em usuários e conduzir o novo usuário até o primeiro momento jogável:

```txt
Criar conta → Criar campanha → Criar personagem → Iniciar Mesa Viva
```

A regra central é:

> A landing page vende a promessa.  
> O onboarding entrega o primeiro passo jogável.  
> Nenhuma tela inicial deve exigir que o usuário entenda o sistema inteiro antes de começar.

---

# 2. Objetivo da Landing Page

A landing page deve explicar rapidamente:

- o que é o Cronofábula;
- para quem ele serve;
- qual problema resolve;
- por que a IA existe;
- por que o mestre continua no controle;
- como a campanha permanece viva;
- como começar.

Mensagem principal:

```txt
Cronofábula é uma plataforma de RPG com IA para campanhas persistentes.
```

Promessa emocional:

```txt
Quando o tempo separa a mesa, a fábula continua.
```

Slogan oficial:

```txt
Sua campanha viva no tempo de cada jogador.
```

Apresentar o produto em até 5 segundos.

### Elementos

- logo;

- slogan;

- descrição curta;
- botão primário;
- botão secundário;

### Texto sugerido

```txt
Cronofábula

Sua campanha viva no tempo de cada jogador.

Uma plataforma de RPG com IA para campanhas persistentes, onde o mestre mantém o controle, os jogadores continuam a história e cada decisão fica registrada na crônica da mesa.
```

### Botões

```txt

```

### Regras visuais

- fundo pergaminho ou azul meia-noite;
- logo central ou à esquerda;
- destaque dourado no botão principal;
- textura arcana sutil;
- sem poluir com muitas informações.

---

## 4.2 Seção Problema

### Título

```txt
Campanhas não morrem por falta de história. Morrem por falta de tempo.
```

### Texto

```txt
Todo grupo de RPG conhece esse problema: agendas não batem, sessões atrasam, detalhes se perdem e o mestre precisa carregar tudo sozinho.

O Cronofábula foi criado para manter a campanha viva entre uma sessão e outra.
```

### Pontos de dor

- jogadores esquecem pistas;
- mestre esquece NPCs;
- campanhas ficam paradas por semanas;
- anotações se espalham;
- cada jogador lembra uma versão diferente;
- o mundo não continua fora da sessão.

---

## 4.3 Seção Solução

### Título

```txt
Uma mesa viva para campanhas persistentes.
```

### Texto

```txt
No Cronofábula, cada campanha tem personagens, cenas, NPCs, mapas, inventário, diário, dados, combate, crônicas e IA contextual.

O sistema guarda o estado do mundo. A IA ajuda a narrar. O mestre decide o que vira canônico.
```

### Cards

#### Mesa Viva

```txt
Jogue cenas narrativas com chat, ações, rolagens e NPCs presentes.
```

#### Mapa Vivo

```txt
Controle onde cada personagem está, quais locais foram descobertos e o que cada jogador pode ver.
```

#### IA Contextual

```txt
A IA recebe apenas o contexto permitido e atua como narradora auxiliar, não como dona da história.
```

#### Crônicas

```txt
Transforme sessões em registros oficiais para continuar depois sem perder a memória da campanha.
```

---

## 4.4 Seção Mestre no Controle

### Título

```txt
A IA ajuda. O mestre comanda.
```

### Texto

```txt
A IA do Cronofábula não substitui o mestre. Ela narra, sugere, resume e interpreta NPCs, mas não revela segredos, não altera inventário, não move personagens oficialmente e não transforma fatos em cânone sem aprovação.
```

### Lista

```txt
O mestre aprova recompensas.
O mestre revela locais secretos.
O mestre corrige a IA.
O mestre define o que vira crônica oficial.
O mestre controla NPCs, mapa e combate.
```

# 11. Regras de Segurança do Onboarding

## 11.1 Não criar dados mock em produção

Nunca criar automaticamente:

- campanhas falsas;
- NPCs falsos;
- personagens falsos;
- mapas falsos;
- crônicas falsas;

em tabelas reais do usuário sem consentimento claro.

## 11.2 Tour separado

O tour deve ser:

```txt
estático
somente leitura
template
sem misturar com campanhas reais
```

## 11.3 IA no onboarding

A IA pode ajudar a gerar:

- descrição de campanha;
- abertura de sessão;
- ideia de NPC;
- tom narrativo;
- nome de campanha.

Mas tudo deve ser:

```txt
sugestão pendente
editável
aprovado pelo usuário/mestre
```

# 12. Eventos para Analytics

Registrar eventos sem expor conteúdo narrativo sensível.

Eventos recomendados:

```txt
landing_viewed
signup_started
signup_completed
login_completed
onboarding_started
onboarding_role_selected
campaign_created
invite_code_used
character_created
first_session_created
first_scene_created
first_dice_roll
first_ai_generation
mesa_viva_opened
```

Não registrar em analytics bruto:

- segredos de campanha;
- mensagens privadas;
- conteúdo de diário;
- prompts completos;
- tokens;
- dados pessoais sensíveis.

# 16. Decisão Oficial

```txt
A primeira experiência do Cronofábula deve levar o usuário rapidamente para uma campanha ou personagem.

A landing page deve vender a ideia de campanha persistente com IA controlada.
```
